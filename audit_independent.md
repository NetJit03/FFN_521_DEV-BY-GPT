# Independent audit of the supplied EC521 project

Audit date: 2026-10-20 (Asia/Bangkok). All ten original Python scripts and all six pre-existing experiment CSV files were read. The original scripts were not executed because they write existing output names and some evaluate historically used test sets. No original file was modified for this audit.

## Scope and source inventory

Read in full: `FFN_classification.py`, `FFN_classification_comparison.py`, `FFN_classification_weight_tuning.py`, `FFN_classification_resampling.py`, `FFN_regression.py`, `FFN_regression_comparison.py`, `FFN_Regression_Improved.py`, `drop_out.py`, `early_stopping.py`, and `FFN_feature_audit.py`.

Read in full: `classification_validation_results.csv`, `classification_weight_tuning_results.csv`, `classification_resampling_cv_results.csv`, `classification_sampling_ratio_summary.csv`, `regression_validation_results.csv`, and `classification_feature_audit.csv`. These are historical outputs, not newly reproduced experimental evidence.

## High-priority findings

1. **Previously used test sets must be quarantined from new tuning.** `FFN_classification_comparison.py:63-65` defines the stratified 20% test split with `random_state=1`; lines 489-509 explicitly evaluate baseline and selected models on it. `FFN_regression.py:31-33`, `FFN_regression_comparison.py:38-40`, `FFN_Regression_Improved.py:30-32`, `drop_out.py:30-32`, and `early_stopping.py:30-32` use the unstratified 20% split with the same seed and subsequently evaluate it. The source and existing result artifacts establish a meaningful historical exposure risk; they do not establish every execution's history. The classification pool and regression pool each contain 9,933 rows, intersect in 1,999 rows, and have a union of 17,867 rows. The 31,797 rows outside both pools contain 474 poor households. A newly shuffled partition of the same dataset cannot be described as pristine external data. Do not tune after inspecting a historical test score.

2. **Threshold selection scores are optimistic if reported on the same labels.** `FFN_classification_comparison.py:404-410` chooses thresholds on validation labels and lines 421-451 score and rank those thresholds on the same labels. `FFN_classification_weight_tuning.py:397-407` does the same for seven weights. Those values are model-selection scores, not unbiased generalization estimates. By contrast, `FFN_classification_resampling.py:278-304,395-433` already uses an inner threshold split and a separate outer fold correctly; preserve this design.

3. **Imputation must remain inside fitting splits.** `FFN_classification.py:34`, `FFN_regression.py:24`, `FFN_Regression_Improved.py:23`, `drop_out.py:23`, and `early_stopping.py:23` fill missing values before splitting. This is a protocol defect and would also impute missing target labels. For this particular CSV, the only missing feature after proper binary conversion is constant-observed `electcon`, and targets are complete, so the audit does not claim a measurable variable-feature leakage benefit occurred in these historical runs. The newer classification comparison/weight-tuning scripts correctly fit the imputer on training data (lines 81-85), as does `FFN_regression_comparison.py:61-65`.

4. **Regression comparison silently loses the electricity feature.** `FFN_regression_comparison.py:22` calls `df.replace(...)` without assignment or `inplace=True`; `Yes` is then coerced to missing at line 23. A median imputer drops the all-missing electricity column. Proper conversion is necessary even though this particular feature becomes constant after imputation and contributes no variable information. Drop or retain it explicitly and consistently in all new comparisons.

5. **Existing regression validation estimates are also selection scores.** `FFN_regression_comparison.py:292-319` selects checkpoints using validation loss, then lines 331-344 evaluate those checkpoints on the same data, and lines 417-420 choose a method. This is a conventional development procedure, but the reported validation RMSE for the chosen method is not independent evaluation. Use an outer evaluation fold untouched by checkpoint selection and configuration selection.

## Additional findings and interpretation

- The original network is input -> 64 ReLU -> 32 ReLU -> 1, Adam learning rate 0.001, 50 epochs, batch size 64 for classification and 32 for regression. Baselines should preserve architecture, loss, learning rate, batch size, and fixed epoch budget while correcting the evaluation protocol. Call this a faithful architectural/training baseline under corrected evaluation, not a bitwise replay of the original scripts.
- Resampling is correctly performed only on fold-training data (`FFN_classification_resampling.py:348-367`). Its scaler is fit on fold-fit data (`:332-334`). However, it lacks imputation, hardcodes a 0.05-0.95 threshold grid, and uses one initialization (seed 0) over three folds. The current non-electricity input matrix is complete, but future missing values would break it. A minimum threshold of 0.05 can miss useful operating points with a 1.55% prevalence.
- Fixed epochs after random oversampling imply more optimizer updates and more examples processed. `FFN_classification_resampling.py:202-243` trains every expanded dataset for 50 epochs; row count and step count should be reported. If matching updates, record the change explicitly because it differs from a fixed-epoch comparison.
- Weight tuning and single holdout validation can overfit the small number of poor observations. The supplied single validation set has 62 positives, as recoverable from the precision/recall denominators and the stratified split. Report fold variation and sensitivity to initialization; do not claim a method universally wins from the largest validation F1.
- The historical resampling CSV reports mean F1 0.17246 for threshold-tuned baseline and 0.16905 for weighted BCE; mean AP is 0.11110 versus 0.12065. ROS mean F1 values are approximately 0.14143-0.14807. Thus the historical evidence does not justify declaring weighting/oversampling uniformly superior. These are descriptions of existing files only.
- The historical regression comparison lists dropout validation RMSE 3,776.40 and original baseline 4,062.42. Because this uses one selected validation partition, this audit does not promote dropout before new independent comparisons.
- Legacy scripts save neither trained-model artifacts nor split indices, environment versions, run manifests, optimizer-step counts, nor new-data inference commands. These are needed for the submission package.

## Dataset schema verified directly

- 49,664 observations, 34 columns: two outcomes and 32 candidate predictors.
- `pov_exp`: 48,895 non-poor and 769 poor (1.548405% poor).
- `rspcexp23`: all positive; minimum 966, median 6,758, mean 8,442.415975, 90th-percentile order statistic 14,941, 95th 19,021, 99th 30,905, maximum 360,795. The quoted percentiles use sorted-index `int(n*q)` and are descriptive, not model-selection thresholds.
- `electcon`: 49,634 literal `Yes` values and 30 literal `None` values. After conversion/imputation it is constant one. No other feature is missing after the stated binary conversion.
- Five region indicators sum to one on every row. The four age-share variables sum to approximately one (floating-point range 0.99999998-1.00000005).
- No exact duplicate full rows. There are 2,023 excess rows with duplicate predictor patterns; this does not prove repeated households. Their outcomes differ. Household/group identifiers and survey weights are unavailable in the supplied columns.
- Categorical binary variables coexist with age, schooling, and four numeric shares. Ordinary SMOTE on all one-hot columns would create invalid fractional categorical values. SMOTENC is technically possible after collapsing the region indicators to one category, using only training data and then re-encoding region. However, generated schooling/age values and cross-feature household constraints require scrutiny. A limited ROS comparison has lower implementation risk under the deadline; skipping SMOTENC with this explanation is defensible.

## Recommended feasible experiment protocol

1. Freeze and hash originals, dataset, splits, candidate lists, and random seeds. Put new work only in the new submission directory or an authorized separate branch. Preserve historical test membership and record how it is handled.
2. Use a compact predefined candidate set. Retain the 64/32 original architecture. Classification: original BCE at 0.5 and independently chosen threshold, a few modest/full-ratio BCE weights, one or two ROS ratios, and at most one regularized BCE variant. Regression: original, early stopping, dropout, combined regularization, and one Huber or log-target candidate if feasible. Do not expand searches in response to final test results.
3. Use the same outer folds for candidate comparisons. Classification requires stratification; regression can share stratified poverty folds for a common evaluation sample if documented, or use K-fold. All imputation/scaling and optional target transformations fit on the relevant fitting rows only. All ROS/SMOTENC happens after splitting and on fitting rows only.
4. Inside each outer training fold, keep checkpoint-selection data separate from the outer evaluation data, and keep classification threshold-calibration data separate as well. A fixed-epoch model can still share the same fit rows for fairness. If data are too scarce, checkpoint and threshold selection may share inner development data, but that reuse must be disclosed; the outer fold remains independent of both choices.
5. Ideally nested CV selects configurations within each outer fold and estimates the full selection procedure on that fold. If using CV to rank predefined candidates without an additional nested layer, report all candidate fold results and explicitly call the winner's CV score a selection estimate. A conservative rule based on paired folds/seeds can retain the baseline when improvement is unstable.
6. Report classification F1, precision, recall, AP, confusion matrix, PR curve, threshold, and prevalence. Describe precision/recall trade-offs. Report regression RMSE, MAE, R² in the original units, residual plots, and group/tail errors (region, rural status, and consumption bands defined from fitting data). Investigate the very large target tail before choosing a method on aggregate RMSE alone.
7. Record epochs run, selected checkpoint epoch, updates actually executed, rows fitted/resampled, and wall time. Save per-row out-of-fold predictions and per-fold metrics so aggregate results can be independently recomputed.
8. Freeze model-selection decisions before any descriptive evaluation on historically exposed test pools. Such results can be a sensitivity check, but cannot repair historical exposure or establish external validity. Reserve truly independent future data for external validation.

## Limits that belong in the final report

The CSV supports within-survey predictive association. It provides no survey weights, sampling-cluster/household identifiers, temporal replication, or externally independent cohort. Row-level random CV does not establish performance in future years, unseen provinces, or the national population. Rare-positive precision and recall have substantial sampling uncertainty. Three folds and a small number of seeds do not support formal claims of statistical significance, especially when training sets overlap. Report observed differences and variability without inventing significance or independence.
